# T-012 — Thin server and static host (2026-09-15)

Owner: orchestrator; implemented directly by the orchestrator (same delegation posture
as T-011: GLM rate-limit pattern, small well-scoped backend task, full context already
held).

## What was done
- `src/static.ts` — MIME extension allowlist (html/js/css/svg/png/jpg/webp/ico/woff2/
  json/txt); `resolveStatic(root, urlPath)`: null-byte + decode-failure rejection,
  `path.normalize` traversal guard (resolved path must stay inside root), extension
  must be allowlisted, must exist as a file; `streamStatic()` with no-store +
  nosniff headers and HEAD support (headers only).
- `src/http.ts` — `createAppServer({webRoot})` on Node built-in HTTP (no new deps,
  ADR-011): GET/HEAD static + SPA fallback to index.html (documented §6.2
  "404 → SPA fallback"); `POST /api/nim` boundary with JSON content-type check (415),
  1 MB body bound with hard connection destroy (413/safe abort), malformed-JSON (400),
  structural validation `{ request: string }` — responds `{fallback:true}` until T-013
  wires the adapter; 405 for other methods. Engine solving stays in-browser; no
  backend solve round-trip exists.
- `src/index.ts` — real entry: `PORT` (default 4173) + `WEB_ROOT` env (defaults to
  `packages/web/dist` relative to server dist), logs startup + contract probe.
- `packages/server/package.json` — added missing `@kolher/engine` dependency;
  tsconfig excludes `*.test.ts` (mirrors engine pattern).
- Tests: `src/server.test.ts` — 13 integration tests on a real listening server
  against a tmp web root: static serving, root/SPA routes, encoded + null-byte +
  dot-segment traversal (nothing outside root and no non-allowlisted file is ever
  served), valid /api/nim fallback, oversized-body safety (no payload leak),
  415/400/405, and offline-start-by-construction.

## Design notes
- No new ADR: this is exactly ADR-011/SYS-ARCH §6.2 as documented (built-in HTTP,
  static mount + bounded /api/nim only, path allowlist, body-size bound). No
  deviations from spec were needed.
- Non-allowlisted/missing file paths fall back to index.html per the documented
  "404 → SPA fallback" behavior; traversal attempts therefore leak only the SPA
  shell, never files.
- Oversized requests are destroyed mid-upload rather than buffered — the 1 MB
  bound cannot be bypassed by chunking.
