# T-007 — Compatibility graph and C7 validation (2026-09-15)

Owner: orchestrator; implemented by backend-agent (delegated), reviewed independently.

## Starting point
T-003 (catalog pipeline) had already landed a partial foundation in
`packages/engine/src/catalog/graph.ts`: `defaultOk` (white-ware neutral, else
finish-family intersection), `compatibilityGraph` (veto > force > default precedence,
symmetric closure, sorted keys/values), `substituteMap`, `familiesOf`. T-007 reused
these rather than rewriting them; the missing piece was the C7 evaluator itself and
its test matrix.

## What was done
- New `packages/engine/src/rules/c7_compat.ts`:
  - `evaluateC7(bindings, catalog, features, config?)` — HARD pair-level rule per
    OPT §5. Every bound-SKU pair checked against `CatalogState.compatibilityGraph`
    (SCHEMA §7.6). Dangling/unknown binding ids fail as `c7-sku-not-in-graph`; every
    pair touching an unknown counts incompatible. Full trace, no short-circuit: all
    failing pairs and constraints enumerated in `measuredDeltas` (`pairsChecked`,
    `incompatiblePairs`, `failedFeatureConstraints`, `wallMountFixtures`) and the
    explanation string.
  - `c7FeatureSet()` maps `InputSet.featureConstraints` (OPT §2.3, typed in
    contracts/input.ts) onto a typed `C7FeatureSet {required, forbidden}`.
  - Mounting (ADR-019): exactly-one-mounting-tag verified deterministically per SKU;
    `wall_mount` recorded as a carrier-wall consequence delta + config note. C7 is
    NOT a wall-construction authority — catalog stays descriptive, rules decisive.
  - Substitutes: `CatalogState.substitutes` (from `substituteMap`) remains the
    explicit relaxation input, reused unchanged.
- `C7_CONFIG` explanation extended with the mounting note (values unchanged).
- Tests: `c7_compat.test.ts` — 13 tests covering the T-007 acceptance matrix:
  override precedence (veto beats force beats default), finish-harmony default rule,
  feature-match pass/fail/no-short-circuit, mounting invariant, substitute closure
  (symmetry/sorting/dangling+self-drop), and the quarantine gate (DANGLING_REF /
  SELF_REFERENCE / BAD_MOUNTING rows never enter graph or candidates — verified
  empirically against `buildCatalog`, since T-003 enforces it at load).

## Modeling decisions
Recorded as ADR-025 in `docs/DECISIONS.md`:
- Required feature tags: **candidate-level coverage** (at least one bound fixture
  carries the tag) — OPT §5 is ambiguous between per-SKU and candidate-level.
- Forbidden tags: **per-SKU** (no bound fixture carries one). Forbidden tags enter
  via the engine-level `C7FeatureSet`, not via a change to the InputSet contract.
- Quarantine gate stays authoritative at load; C7 only double-fails unknown ids.
- One-line change path if product wants per-SKU required matching — amend the ADR
  first.
