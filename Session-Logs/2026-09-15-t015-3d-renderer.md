# Session log — T-015 procedural 3D renderer (2026-09-15)

Owner: orchestrator; reviewed and completed the existing frontend renderer, then ran
targeted implementation and regression checks.

## Scope

T-015 was listed as `PENDING`, but `packages/web/src/render3d/` already contained the
scene-spec builder, Three.js scene graph builder, OrbitControls mount, demo fixture, and
tests. The audit found two correctness gaps in that implementation and fixed them:

- Catalog descriptor axes now follow SCHEMA §6.1: `x` is width, `y` is fixture height,
  and `z` is depth away from the wall. Previously `y` and `z` were swapped.
- Room wall segments now carry deterministic Y-axis rotation, so vertical side walls are
  rendered along the room boundary instead of as unrotated X-axis boxes.
- Fixture primitives resolve a deterministic wall-facing frame from the authoritative
  engine AABB and room polygon, including side-wall orientation. The T-014 render
  contract now retains the solver's `wallStripId` so corner placements cannot be
  misclassified from AABB boundary contact alone.
- Non-finishable fixture primitives use the catalog ceramic-white default. Finishable
  primitives use the chosen catalog finish swatch.
- Missing catalog SKUs now fail the render contract instead of creating a guessed fallback
  mesh; this preserves `render = catalog geometry` and prevents a visible fixture from
  losing BOM/catalog provenance.
