## What was done
- `solver/archetypes.ts` — archetype template table lives in config (config.ts /
  config-types.ts, matching existing style): Compact-guest, Budget-family,
  Spa-master, Full/Luxury with per-class count ranges. `filterArchetypes`
  deterministically filters by classCountRanges/preferredClasses/room/budget.
- `solver/bind.ts` — SKU binding with C7 pair-level compatibility (via T-007's
  `evaluateC7` graph) and cost-aware pruning (branch dies when partial integer-INR
  cost > bMax). Deterministic SKU order: price asc, then model_id.
- `solver/place.ts` — wall-strip CSP: (wall assignment → 1D order → discrete slot
  on `slotGridMm` 25 mm grid). §9 deterministic ordering: plumbing-anchor-first
  (WC→shower→basin→tub→extras), then largest-footprint-first; walls sorted by
  usable length/affinity. Forward-checking prunes on C1 overlap plus C2 front AND
  side corridors. Bounded by the shared `backtrackBudget` (10000); exhaustion
  routes to typed infeasibility — never a hang.
- `solver/assemble.ts` + `solve.ts` — `runConstructiveSolver(input, catalog)`:
  Step-01 gate first (unconfirmed → `gate-blocked`, solver never runs), then
  layered pipeline, full C1–C6 + C7 + budget validation on every emitted candidate;
  validity flags are measured facts. Candidate id = canonical sorted-SKU join;
  output list deterministically sorted (id, then cost). Infeasible result carries
  measured blockers only (relaxation menus are T-010 scope).
- Solver barrel exported from `packages/engine/src/index.ts`.
- Tests: `solver.test.ts` — 8 tests: typical-room fixture over `loadCatalog` emits
  only fully-validated candidates (re-checked in-test), run-twice determinism
  (JSON-identical), budget exhaustion → typed infeasible, unconfirmed gate,
  latency.

## Defects found and fixed during integration (by the agent, confirmed in review)
1. **C4 dangling-zone false blocker**: `makeFixture` emits `zones: []` because the
   room rep has no zone derivation anywhere — otherwise C4 failed every candidate
   on a requirement nobody declared. C4 is currently vacuous as a result; parked in
   TODO.md with the fix path.
2. **C2 forward-check gap**: the placement approximation only checked front
   corridors, so side-clearance failures (two WCs 475 mm apart vs 450 mm side spec)
   survived to full validation and killed every candidate. Fixed to prune on side
   corridors too.
