# Session log — T-013 AI adapter and offline fallback (2026-09-15)

Orchestrator-delegated to backend-agent; independently reviewed and verified.

## Scope executed
`packages/server/src/ai/` — the SYS-ARCH §6.3 AICli seam: `tasteToFeatures`,
`photoProposal` (advisory-only, empty proposals per ADR-009), `narr` (receipt-bound),
`tradeoffs` (rephrase-only). NIM client (OpenAI-compatible chat completions,
`moonshotai/kimi-k3` default, `.env`-switchable `NIM_API_KEY/NIM_BASE_URL/NIM_MODEL/
NIM_TIMEOUT_MS`), hand-rolled strict validators (no zod — zero-dep posture), and a
deterministic offline template twin. Any NIM failure (no key, fetch throw, non-2xx,
timeout, schema-invalid, unknown-vocab, injection guard) degrades to the offline twin;
the adapter never throws.

## Key decisions / deviations (documented, not ADR-worthy)
- `/api/nim` envelope extended beyond the documented `{ request, image? }` with typed
  payload fields (`text`/`receipt`/`menu`) and a task discriminator on `request` ∈
  {taste, photo, narrate, tradeoffs}; responses `{ok:true,task,...}` or
  `{fallback:true,reason,task,...}`. SYS-ARCH §6.2's one-endpoint-three-tasks shape
  requires discrimination; the extension is comment-documented in http.ts.
- Adapter methods are async and return `AiResult<T> {value, fallback, reason}` — §6.3's
  sync signatures cannot express the fallback posture.
- `tasteToFeatures` returns `null` constraints for gibberish (honest) instead of
  inventing empty constraints.
- Prompt-injection tripwires on taste text/tones; narration validated so every number
  must appear in the receipt JSON (ADR-14 receipt-binding); tradeoff rephrases cannot
  introduce digits absent from `tradeoffDelta`.
- Secrets: key read once in `server/src/index.ts` from env, held server-side only,
  never echoed in errors/responses; adapter lives solely in the server package so the
  web bundle cannot contain it.
